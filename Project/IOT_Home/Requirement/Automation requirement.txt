Suggestions for Automation requirement.txt
To further improve the robustness of the system, I suggest the following enhancements to the requirements:
1. Define Sensor Thresholds: Instead of "Low" or "High" light, specify approximate ADC values (e.g., < 300 for dark, > 700 for bright) to ensure consistent behavior across different LDR hardware setups.
2. Power Failure Recovery: Specify the "Fail-Safe" state for relays. For example, should the Exhaust Fan stay OFF or return to its previous state after a power outage?
3. Background Notifications: For critical alerts (like the Gas Leak in the Kitchen or the "Buzzer Alert" in the Toilet), consider a requirement for Firebase Cloud Messaging (FCM) so the phone receives notifications even when the app is closed.
4. Deep Sleep Support: If any of these NodeMcu units are to be battery-powered, requirements for Deep Sleep (waking up only on PIR interrupt or timer) should be added to extend battery life.
5. Log Rotation/Management: Since NodeMcu has limited internal flash memory (LittleFS), a requirement for "Circular Logging" (deleting oldest entries when full) or an "Export to Email/Cloud" feature would be beneficial for long-term data preservation.
6. Calibration Interface: Add a requirement for a "Calibration Mode" in the Android App settings to adjust sensor offsets (like DHT11 temperature correction) without reflashing the firmware.
1. MQTT Image Compression: Since MJPEG over MQTT can be bandwidth-intensive, consider adding a requirement for the ESP32 to reduce JPEG quality (e.g., from 10 to 20) or frame size when using MQTT mode.
2. Credential Management: Move WiFi and MQTT credentials into the SharedPreferences-backed configuration on the NodeMcu/ESP32 so they can be updated via the Android app without reflashing the devices.
3. Heartbeat Monitoring: Add a "Last Seen" timestamp for each node in the intermediate SmartHomeActivity menu so the user can see which devices are offline at a glance.
4. WebSocket vs TCP: Note that while the Android app supports WebSockets (ports 8000/8884), the standard ESP8266/ESP32 PubSubClient library uses TCP/SSL. For full failover to WebSocket ports on the hardware side, a different MQTT client library may be required.
